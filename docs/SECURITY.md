# SSH security design (v0.3.0)

## v0.4 session library and release additions
- Session/folder changes are validated in Rust and atomically replace a versioned catalog. An OS file lock serializes cooperating writers, and comparison with the last loaded bytes rejects stale updates. Reload after an external change; disk/write failures do not publish a new in-memory state. A legacy array receives a non-overwritten backup before its first migration write. Unknown legacy/import fields are rejected before a raw legacy backup could copy credential fields.
- Import uses an explicit native JSON picker, a 4 MiB bound, schema/field validation and preview/confirmation. Imports receive fresh session IDs and cannot replace existing sessions by ID. Exports contain typed metadata only, never the vault, private-key file contents or known-host trust. File selection is explicit; no generic frontend read/write-path API is exposed.
- Editor discovery checks bounded standard locations/registry/PATH entries. The native EXE picker and save validation do not execute programs. Actual editing remains outside v0.4.
- Pasted HTTP(S)/SSH addresses are normalized to SSH endpoints; protocol/port defaults and host-key verification are not weakened. Embedded credentials, paths/query/fragments and ambiguous hosts are rejected with actionable feedback.
- Release publication is limited to main and consumes a successful same-repository PR build at that exact commit. Receipt source SHA, workflow run, installer names/types, byte lengths and SHA-256 values are checked before publication. Releases are drafted with all assets before becoming visible and are not overwritten on subsequent same-version pushes. These receipts are provenance checks, not code signing or an independent security audit.

The SSH trust/credential design below is retained for v0.4.

This is a test-build security design, not a claim of production readiness or a completed independent audit.

## Trust boundaries
- Rust owns TCP, the libssh2/OpenSSL SSH engine, private-key file access and Windows Credential Manager calls. The webview receives public fingerprints and an opaque transport ID, not private-key contents or saved passwords.
- Passwords/passphrases entered in the UI cross narrowly scoped IPC once; visible fields are immediately cleared. JavaScript strings cannot be reliably zeroized. Rust auth buffers use zeroize on drop, with best-effort handling of library-owned copies. No secrets are written to JSON, command arguments, application logs or telemetry.
- Saved session data contains connection metadata, authentication method and an existing key-file path only. Editor preference/path is metadata and does not execute a program in this release.

## Server identity
- TCP connect, SSH handshake and SHA-256 fingerprint collection happen before authentication. A pending connection is bound to an opaque, expiring ticket. Approval authenticates that same connection, avoiding a second unverified handshake.
- TermiX stores public host keys in its own local known-hosts file. It does not silently import, replace or edit the user's OpenSSH known_hosts.
- First-seen keys require explicit fingerprint approval. Changed keys block the connection, show old/new fingerprints and require independent verification plus the exact hostname and an explicit replace decision.
- Rust enforces these decisions independently of the UI and rechecks the persisted pin snapshot before authentication. Corrupt trust files fail closed and are not overwritten.
- Algorithm preferences exclude SHA-1 host-key signatures, DSA, group1, CBC and SHA-1 MAC fallback. Unsupported legacy servers fail negotiation instead of weakening policy.

## Credentials
- Agent authentication never enables agent forwarding. It tries at most 16 local identities within a deadline; a server may enforce a smaller authentication-attempt limit. Existing encrypted private keys are referenced by absolute path, not copied into app storage; passphrases are not saved.
- Saving a password is opt-in, Windows-only, and happens after successful host verification, authentication and terminal allocation. Windows stores it under a per-endpoint/username TermiX generic-credential target. Stored mode reads the password entirely in Rust. A forget action deletes that specific target.
- The OS credential vault does not protect against malware or another program running as the same user. Remote shells may independently save command history; TermiX's in-memory scrollback policy does not govern that history.

## Lifetime and resource limits
- Connections, authentication work and pending trust tickets are bounded. DNS/connect/handshake operations have deadlines/timeouts. No arbitrary local SSH command line is constructed.
- Non-blocking channel I/O is serialized per transport; input is ordered/bounded, output is pulled at the renderer's pace, resize is coalesced. Closing a tab/window shuts down its socket. Reconnect repeats server verification.
- Closing an in-flight authentication dialog ignores the result and closes a late successful transport; underlying blocking authentication may finish at its timeout. A stalled local agent may depend on the agent's own responsiveness. These need manual failure-path review before production use.

## v0.5 SFTP scope (automated checks passed; manual review remains)

SFTP uses the existing host-verified/authenticated SSH transport. No new passwords/trust decisions or shell interpolation. Blocking-pool workers handle bounded directory listings (5,000 entries), 64 KiB streaming chunks and per-operation 10-second EAGAIN deadlines (a stuck protocol operation closes the transport to avoid reusing indeterminate state); one file operation per connection runs at a time. Native owner-bound Open/Save dialogs authorize specific local paths, never arbitrary local-path IPC. Only regular files transfer; symbolic links are displayed but not followed. Remote servers remain trusted for filesystem semantics and may race path/stat operations; metadata checks detect common conflicts but cannot prove content identity or defeat a malicious server.

Cancellation waits for a pending nonblocking protocol operation to complete (up to its deadline) before stopping; a final rename already in flight may complete. Transfers write exclusive UUID sibling partial files and commit after success. Remote replacement requires explicit opt-in and atomic rename support; unsupported operations fail instead of deleting the original. Downloads atomically replace after native overwrite confirmation and metadata checks. Interrupted connections/crashes can leave .termix-UUID.part files; no automatic resume or recursive deletion occurs. Local permissions/ACLs follow the selected directory; remote new files default to mode 0600. Local path races by another process running as the user are outside this app boundary. Installed native picker and server interoperability checks remain manual.

## v0.6 editor and Windows integration (automated verification passed; manual review remains)
Monaco is bundled locally and lazy-loaded; editor workers are restricted to self/blob and no CDN is used. Remote files are bounded to 2 MiB of UTF-8, no NUL bytes, regular files only, eight tokens per SSH transport. Canonical path, original content SHA-256 and permission bits are held in Rust. Saves re-read the entire remote content before and after writing an exclusive sibling partial file, restore permission bits and require atomic replacement. These checks detect common concurrent changes; SFTP has no universal server-side compare-and-swap and cannot defeat a malicious server/race in the final rename interval. No forced overwrite option is provided after a conflict. Explicit Reload server updates the saved revision after a discard confirmation.
External editors run only after an explicit action using the saved validated EXE, no shell and one working-copy path argument. Working copies use random per-user temp subdirectories (0700 on Unix, inherited per-user temp ACLs on Windows). No watcher automatically uploads content. Reload and server save remain explicit; crash leftovers are disclosed. User-selected editors and other processes running as the user are trusted. Closing a buffer removes its known copy without recursive directory cleanup; external editors can recreate files or backups.
The WebView2 native file-drop handler is disabled to permit HTML session/tab dragging; this does not add a generic native file path IPC. Installer process checks use Tauri's exact-path Restart Manager integration, not process-name taskkill. Native upgrade preservation and interactive drag/installer behavior must be distinguished from browser/mock tests.
Build 41885597244 passed 28 native, 34 frontend, 23 browser and 7 release-receipt checks. The native external-editor fixture writes a single per-user working copy and verifies that the server file is unchanged until explicit save. The exact shipped EXE/MSI were built and a checksum-verified running v0.5 install upgraded to v0.6, with catalog/settings/known-hosts byte preservation plus final executable version and shortcut icon verified. This is separate from native drag-gesture tests, interactive installer cancellation, broad interoperability and an independent audit.
## v0.7 workspace and productivity boundaries

Direct external opening uses the same validated configured executable and bounded document token as v0.6, without loading Monaco. Reload/review and server save are explicit; no watcher or automatic upload is added. Close the external editor before removing its working copy. Closing TermiX can leave temporary copies as described above.

The optional shared sidebar and split view reuse existing verified transports; expanding directories never opens a new SSH connection or recursively follows links. Remote tree caches are bounded to 5,000 displayed/cached entries and 12 child levels and reset on navigation/refresh. Two-file comparison is read-only and retains the existing conflict-checked save flow.

workspace.json stores bounded typed session IDs or allowlisted local profiles, order, pin/colour and widths. It contains no remote contents, terminal output/history, credentials or command snippets. Restore is an explicit action; SSH tabs remain disconnected until normal Reconnect/host-key/authentication flow. Deleted session references are skipped. Layout persistence is best effort, separate from the session catalog and its conflict handling.

Named command snippets are memory-only in this release (50 snippets, 4,096 characters each), with a visible target and confirmation before each run. No recording, automatic execution or JSON storage. Do not enter secrets. Context-menu multiline paste requires confirmation; standard keyboard paste remains xterm behavior and may execute commands in the selected shell. Clipboard APIs may be unavailable under some desktop policies; normal keyboard shortcuts remain available. No automatic output logging is introduced.

## v0.8 work under verification

Portable mode requires portable.flag beside the executable. Data and WebView profile go to its adjacent data folder; no installed catalog is imported automatically. Its vault namespace includes a hash of the portable folder, so credentials remain machine/user/location-bound rather than travelling in the ZIP. Packaging uses an explicit distributable-file whitelist, and receipt validation rejects ZIPs containing user data.

The EXE uninstaller asks before removing only generic TermiX:ssh:<64 hex> credentials, defaults to No and skips deletion on silent upgrades/uninstalls. The fixed cleanup CLI exits before creating a webview and refuses portable execution. MSI uninstall retains credentials. Other vault namespaces, users and private-key files are outside this cleanup.

Saved commands are bounded typed plaintext definitions. They are not a secret store: the UI warns against secrets, and obvious private-key/assignment patterns are rejected, but arbitrary command text cannot be comprehensively classified. No automatic execution occurs. The selected target and command are confirmed at run time.

External copies remain managed without a blocking opening dialog. Native/DOM focus and foreground-only checks hash bounded regular UTF-8 copies; changed content must be stable across two checks before asking to transfer. The approved snapshot is sent through the existing remote-conflict check. No automatic upload/watcher or arbitrary local paths are exposed. Closing the app warns about open external copies. Crash/disconnect leftovers and broad external-editor interoperability remain manual concerns.

Remote file creation is exclusive and never truncates an existing file. Deletion requires a UI confirmation and is limited to regular files or empty directories; recursive deletion and link traversal are not provided.
